## 4. Architectural Boundaries & Q1/Q2 Preservation

1. **Logical vs. Physical Separation:** Maintained. `tables_relations` in canonical inspection captures logical relation objects separately from connection summaries.
2. **Calculated Status vs. Formula:** Maintained. Calculation formulas exist purely in design-time TWB inspection evidence and are never assumed to be exposed by live Extensions API objects.
3. **Field Definition vs. Field Instance:** Maintained. The distinction between the 282 base datasource fields and the 1074 worksheet-scoped column instances is explicitly preserved.
4. **Q1 (Field-to-Instance Binding):** Per Phase 03 governance contracts, canonical inspection provides design-time column instances (`column_instances`) and runtime evaluated columns (`dataTableColumns`), but **no programmatic heuristic** is applied to force deterministic binding between design-time instances and runtime IDs. Q1 remains an unresolved architectural question pending future design phases.
5. **Q2 (Dashboard Layout Equivalence):** Preserved as layout metadata without pixel-level normalization heuristics.
